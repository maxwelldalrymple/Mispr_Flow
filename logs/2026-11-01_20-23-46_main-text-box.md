# Paste into the window's main text box when none is selected

**Reported:** if you haven't clicked into a text box, dictation only copies and you have to paste by hand. It should go into the active window's main text input.

**How:**
- `pointer.text_inputs` walks the front window for visible, enabled text areas, fields and combo boxes, at least 40×14 points.
- Skipped: anything inside toolbars, tab groups, menu bars, sheets, lists, tables, outlines, rows, cells, grids or columns, and anything labelled address, search, url, find or filter.
- `main_input` picks the biggest box (text areas ×1.4, boxes in a web page ×1.5). `focus_input` sets `AXFocused` (or clicks it if that's refused) and puts the cursor at the end of the existing text.
- In the widget, when the text-box check says no and `find_text_box` is on (the default), it focuses the main box, waits 0.1 s, checks again, then pastes. Auto-Enter follows. Long dictations in pieces do the same once.

**Measured on the owner's open apps (read only):**
- Chrome: 1 box, the page's chat box (on the page, not the address bar).
- The Claude app: its message box.
- Terminal: its text area.
- Finder: 23 boxes before the list rule, all file names (pasting there would rename a file); 0 after it. So Finder still copies.

**Tests (affected files):**
- `test_pointer`: biggest wins, text area and page boxes weighted, nothing found gives None, the skip lists.
- `test_widget`: pasted into the main box, copied when the window has none, copied when the switch is off.
- `test_settings_models_setup`: the new setting.
- The shared widget fixture now stubs `text_inputs`, so tests never read the real screen.
- All pass.
