# Security audit: Mispr Flow as a publicly downloadable app

**Branch:** `security-audit` · **Date:** 2026-10-01 · **Scope:** the Python engine (`mispr/`), the Swift app (`macos/`), build and signing scripts (`tools/`), dependencies and models, repository contents and git history, and the built `Mispr Flow.app`.

**Goal:** meet what's expected of a publicly trusted, downloadable macOS executable. Verify that nothing leaves the Mac except the hash-checked model downloads.

## Method

Each area was checked with commands whose output is summarized below.

| # | Area | How |
|---|---|---|
| 1 | Network | `git grep` for every network and process API (urllib, sockets, URLSession, curl, subprocess, osascript, mdfind, `Process()`); every URL literal; live connections of the running app and engine (`lsof -i`) |
| 2 | Secrets | regex scan for keys and tokens (OpenAI, GitHub, AWS, Hugging Face, Slack, private keys, `api_key=`) over tracked files **and all git history** (`git log -p --all`) |
| 3 | Personal data | tracked files containing e-mail addresses or home-folder paths; tracked data files (audio, databases, certificates, .env) |
| 4 | Dependencies | versions in `requirements.txt`; known vulnerabilities with `pip-audit` (OSV/PyPA advisory DB) in an isolated environment |
| 5 | Code signing and distribution | `codesign -dv`, entitlements, `spctl -a -vv` (Gatekeeper) on `build/Mispr Flow.app` |
| 6 | Injection | every place spoken or external text reaches AppleScript, a shell, Spotlight queries or file paths |
| 7 | Data at rest | file modes of user data folders, the settings, and the engine log; what the log records |
| 8 | System access | how Accessibility, keystrokes, Finder automation, Full Disk Access and volume control are used |
| 9 | Integrity | model download path (TLS, size, SHA-256, atomic rename) |
| 10 | IPC | the app↔engine channel |

## Results

| # | Finding | Severity | Status |
|---|---|---|---|
| 1 | **Network:** the only outbound code is `models.py` `urlopen`, model downloads from Hugging Face and the sherpa-onnx GitHub releases. Besides that there's a "Learn more" link the user clicks (opens the browser). **No telemetry, analytics, crash reporting or update checks.** `lsof -i` on the running app and engine showed **no open network connections**. | Pass | Verified |
| 2 | **Secrets:** none in tracked files or anywhere in git history. | Pass | Verified |
| 3 | **Model integrity:** HTTPS (TLS verified by default), exact size and pinned SHA-256 before use, `.part` file then atomic rename. A non-HTTPS URL is now refused outright. | Pass, hardened | **Fixed:** HTTPS-only check plus test |
| 4 | **Spoken voice commands were written to the engine log in plain text**, including in Incognito (`switch heard 'Open clawed folder.'`). | **High** (privacy) | **Fixed:** the log records only the length; test `test_the_log_never_holds_what_was_said`. Dictation was already logged as character counts only |
| 5 | **User data folders were world-readable** (`755`, files `644`): voice-recordings, meeting-recordings, Application Support (settings, prompts), Logs. Other accounts on the Mac could read dictations and meetings. | **High** (privacy) | **Fixed:** `storage.lock_down()` makes them owner-only (`700`) at every engine start, which covers every file inside. Tests in `TestPrivateFolders` |
| 6 | **Dependencies not pinned** (`requirements.txt` had names only), a supply-chain risk. | Medium | **Fixed:** exact versions pinned. Next step: hashes (`pip-compile --generate-hashes`) |
| 7 | **`diskcache` 5.6.3** (pulled in by llama-cpp-python) has PYSEC-2026-2447: unsafe pickle deserialization of cache files. No fixed version yet. | Low (not reachable) | **Accepted:** Mispr Flow never uses llama-cpp's disk cache. Re-check with `pip-audit` before each release |
| 8 | **Code signing:** the app is signed with a local self-signed certificate. There's no Team ID and no **hardened runtime** (`flags=0x0`), it isn't notarized, and **Gatekeeper rejects it** (`spctl: rejected`). Fine for development; **a release blocker for public download.** | Accepted (owner's decision) | **Accepted:** the app ships as an **unsigned DMG on GitHub Releases**, with no Apple Developer ID or notarization. Mitigations below |
| 9 | **Injection:** AppleScript gets only fixed text, integers, or a file path escaped for `\` and `"` (`apps._quote`). Spotlight queries get only `\w` word characters from speech. All subprocesses use argument lists with no shell (`mdfind`, `open`, `osascript`, `defaults`). Terminal mode can't add words that weren't said. | Pass | Verified |
| 10 | **Acting on the Mac:** keystrokes, window moves, quitting apps and volume changes happen only on the user's own key press plus speech. Weak app matches never launch apps. The Full Disk Access check only *reads* `TCC.db` and never changes it. Accessibility is used for the hotkey, paste and context only. | Pass | Verified |
| 11 | **IPC:** app↔engine uses the child process's stdin/stdout pipes (no network port or socket), and the engine quits when the pipe closes. | Pass | Verified |
| 12 | **Public repository content:** the knowledge base (chat log) includes the developer's macOS username in file paths and the conversation itself. There are no e-mail addresses, keys or other personal identifiers. | Info | The owner's choice; redact `/Users/<name>` paths if wanted |
| 13 | **Licences:** code MIT. Whisper MIT, Silero MIT, TitaNet CC BY 4.0, AMI and LibriSpeech CC BY 4.0 (gender weights). **Gemma requires its Terms of Use to be shown** to users who download it; today they appear only in the README. | Medium (compliance) | **Fixed:** the setup Models page shows the notice and links the terms (logs/*_gemma-terms.md) |
| 14 | **Memory and clipboard:** audio in an `mlock`ed buffer, zeroed after use. Pasted text is marked transient/concealed and the clipboard restored. Incognito types instead of pasting and saves nothing. | Pass | Verified (existing tests) |

## Release requirements: unsigned DMG on GitHub

**Decision (owner, 2026-10-01):** Mispr Flow is distributed as a free, **unsigned DMG on the GitHub repository's Releases**, without Apple Developer ID signing or notarization.

**What users see:** on first open, macOS says the app "can't be verified" (Gatekeeper). They open it once with **right-click → Open**, or System Settings → Privacy & Security → **Open Anyway**. The README and release notes must say so.

**What every release must still do,** so users can trust the download:

1. **Publish a SHA-256 checksum** of the DMG in the release notes (`shasum -a 256 Mispr-Flow.dmg`). Users verify it before opening.
2. **Build from a tagged commit** (`vX.Y`) on `main` with a clean working tree, so the DMG matches public source code. GitHub's release page links the tag.
3. **Sign the DMG's app with a stable local identity** (the existing "Mispr Flow Local Signing" certificate, or ad-hoc with a fixed bundle ID). This doesn't remove the warning, but keeps macOS permissions from resetting on every update.
4. **Bundle a portable Python** and all libraries inside the app (not the developer's `.venv`). Never ship the developer's models or data: they download and verify on first run.
5. **Include the pinned dependency list and model hashes** (`requirements.txt`, `docs/models.md`) in the release notes, as a simple SBOM.
6. **Show the Gemma terms** at model download (finding 13).
7. **Before each release:** `pip-audit`, the secret scan, the full test suite, and a check that the DMG contains no `voice-recordings`, `meeting-recordings`, `.venv` or logs.

Optional later: Developer ID signing and notarization would remove the warning, if the project ever wants it.
