# Setup restarts from Welcome after allowing a permission

**Branch:** `setup-resume`

**Report** (during the fresh-start test): "it goes back to the beginning of the setup when you exit out of System Settings".

**Cause:** after some permissions (Screen & System Audio in particular), macOS **quits and reopens** the app to apply them. Each reopen started a new engine, so the engine PID changed about every 30 s while permissions were being granted. `SetupFlow.start_step()` always returned Welcome for a user who hadn't finished setup.

Side effect seen in the log: a model download running at that moment restarted with the engine. Gemma finished once the restarts stopped.

**Fix:**
- `settings.setup_step` stores the step reached; `advance` and `back` save it into settings.json, keeping the other keys.
- `start_step()` resumes there, but **never past Allow access while a required permission is missing**.
- A brand-new user still starts at Welcome.

## Tests

`pytest tests/test_onboarding.py tests/test_settings_models_setup.py tests/test_screens_sounds_app.py`: all passed.

- `TestSetupResumes` (3):
  - the step is saved and resumed after a "reopen" (settings read back from disk);
  - it never resumes past Allow access if a required permission was revoked;
  - Back is saved too, and new users start at Welcome.
- The settings file tests were updated for the new `setup_step` field.
