# App switcher: open folders and files, and the Finder permission in setup

**Branch:** `speaker-id`

| Say | Does |
|---|---|
| "open folder Projects" / "open the Downloads folder" / "go to my voice recordings folder" | searches your home folder level by level, so duplicates resolve to the **highest-level** match, and opens it in Finder |
| (in Finder) "open Taxes" | a folder anywhere below the one shown opens **in the same Finder window** |
| (in Finder) "open Budget" | a file below it (matched with or without its extension) opens in its app |
| (in Finder) "open Receipts", not found | "“receipts” can't be found in Docs" |
| (in Finder) "open Chrome" | not in the folder but clearly an app: switches to it |
| (elsewhere) "open Chrome" | switches to the app, as before |

**Search details:**
- Names are matched loosely: "mispr flow" finds `Mispr_Flow`, "voice recordings" finds `voice-recordings`.
- Skipped: hidden folders, Library, `node_modules`, venv, build/dist and similar, and .app bundles.
- Limits: depth 8, a 1.5 s budget. It runs off the main thread, with "Looking…" shown meanwhile.
- On this Mac, finding `Mispr_Flow` from home took 0.17 s and `voice-recordings` 0.02 s.

**Finder control:**
- Same-window navigation and reading the shown folder use AppleScript to Finder. This needs macOS's Automation permission ("Mispr Flow wants to control Finder").
- Setup's permission page now has an optional **Control Finder** row with an Allow… button.
- The status check uses `AEDeterminePermissionToAutomateTarget` without asking, so the page's refresh timer never pops the prompt. Only Allow… asks.
- New-window opening (`open`) needs no permission.
