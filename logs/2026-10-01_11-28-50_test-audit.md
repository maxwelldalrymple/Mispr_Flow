# Test audit: every function tested

**Date:** 2026-10-01 · **Branch:** `ui-tests` · **Catalogue of every test:** [2026-10-01_11-28-50_test-catalog.md](2026-10-01_11-28-50_test-catalog.md) (regenerate with `python tools/test_catalog.py`)

Goal: every function in the app, especially the UI, has unit tests that check what it needs to.

## Method

- **Python:** `pytest --cov=mispr --cov-report=json`, then every function with zero executed lines was listed (coverage.py's per-function data).
- **Swift:** `swift test --enable-code-coverage`, then every function with an execution count of 0 in the llvm-cov export, demangled. Compiler-generated pieces (closures, default-value `??` branches, thunks, property initial values like `@State var hovering = false`) are reported but aren't functions anyone calls.

### Swift: what was added

New test target `MisprFlowTests` (the app target is importable for tests). Changes made only so code could be tested, with behavior unchanged:

- `Engine.sendHook` records commands instead of writing to the engine process; `EngineConfig.arguments` lets a stand-in script play the engine.
- `AppModel(engine:profile:)` and `Profile(defaults:photoURL:)`: tests use temp folders and scratch preferences, never the real ones.
- `NoteModel.makeRecorder` / `probe` / `permissionCheck` / `permissionRequest` / `openSettingsPane`: a fake recorder (protocol `MeetingRecording`) and fake system checks.
- Logic moved out of views into named functions: `KeyRecorder.pick` (key picker), `TranscriptText` (timer, search count, highlight), `NoteWindowController.dockedFrame`, `FlowLayout.arrange(width:sizes:)`, `NotesView.personPage`, `PromptsView.save(_:to:engine:)`, `MoreInsightsView.snippet`, `Profile.setPhoto`, `AppDelegate.makeMainWindow`, `DevTools` (the `--detect` / `--segment` reports).
- Initial-tab options on `InsightsView`, `NotesView`, `MeetingDetailView` so every tab can be rendered.

### Findings while testing

- **Resampler holdback:** converting 48 kHz → 16 kHz returns ~70 ms less than it was given per call; the converter keeps that for its filter and releases it with the next buffer. Over a stream nothing is lost except that fixed ~70 ms when recording stops. Test: `testResamplerMakes16kMonoWithOnlyASmallHoldback`.
- **Offscreen snapshots don't paint native pop-up buttons** (the meeting-type chip): its rendering is checked for crashes and its choices are tested separately.

## Intentionally not unit-tested (and why)

| Function | Why | Covered instead by |
|---|---|---|
| `AppModel.launchAtLogin` setter | would register the test runner as a login item on this Mac | the getter is read in a test |
| `MeetingRecorder.start` / `startMic` / `startSystemAudio` | open the real microphone and capture system audio | the app's `--record-test` check; everything after capture (`ingest`, callbacks, chunking) is tested |
| `Profile.choosePhoto` | shows a modal file dialog | `setPhoto` (what it calls) is tested |
| `main.swift` entry | the process entry point | its reports live in `DevTools`, tested |
| `NoteView.send`, `NoteView.matchCount`, `NotesView.showPerson`, `PromptsView.save()`, `KeyRecorder.toggle/start/handle/choose` | one-line button/keypress handlers that only fire from a live click or key event; each just calls tested logic | `NoteModel.ask`, `TranscriptText.matchCount`, `NotesView.personPage`, `PromptsView.save(_:to:engine:)`, `KeyRecorder.pick` + `AppModel.setDictationKey` |
