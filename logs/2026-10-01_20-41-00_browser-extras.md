# Voice commands: more browser control

**Branch:** `additional-browser-feature` (on top of `security-audit`, which isn't pushed yet)

| Say | Does |
|---|---|
| "tab left" / "tab right" | previous / next tab (⌃⇧⇥ / ⌃⇥) |
| "move tab left" / "move tab right" | moves the tab one place (⌃⇧PgUp / ⌃⇧PgDn) |
| "tab 3", "tab nine" | ⌘1–⌘8; tab 9 is the last tab (⌘9). Spoken numbers after "tab"/"window" are understood |
| "window 2", "go to window one in Chrome" | raises that window of the app (Accessibility), numbered left→right then top→bottom; otherwise "this app has N windows" |
| "next window" / "previous window" | ⌘\` / ⌘⇧\` |
| "tabs side by side", "split tab", "split view" | Chrome's own split view from the tab's menu if present; otherwise "Move tab to new window", then the two windows are tiled half and half (after 0.6 s) |

**Bugs found while building:**
- "tab left" was read as a tab number. Now only "tab <digits>" is.
- "move tab left" was read as app "move" + "tab left". The parser now tries matching without an app name first.

**Real check (read-only):** `apps.windows()` on the running Chrome found its 1 window.
