# App switcher: play/pause, volume, mute mic / tab

**Branch:** `speaker-id`

| Say | Does |
|---|---|
| "pause" / "play" / "resume" | the play/pause media key: whatever is playing (Spotify, YouTube, Music…) |
| "next song" / "previous track" | next / previous media key |
| "volume up" / "louder" / "volume down" / "quieter" | ±10, unmutes |
| "volume 40%" / "set volume to thirty percent" | sets the level |
| "mute" / "unmute" (also "… the sound") | the Mac's output |
| "mute mic" / "unmute mic" | input volume to 0 / back to its old level |
| "mute tab" / "mute tab in Chrome" | presses "Mute site" in the selected tab's menu (Chrome, Brave, Edge, Arc); says it again to unmute |
| "mute Spotify" | in a browser, mutes the tab; otherwise explains that macOS can't mute one app (no per-app volume without extra audio software) and suggests "pause" |

**Mute mic, by voice:** a muted mic would also stop Mispr hearing "unmute mic". So while the switch key is held, the mic is opened just to hear the command, then muted again unless you said "unmute mic". fn dictation stays muted, so nothing reaches your call.

Volume and mic use AppleScript's `set volume`, which needs no permission. Media keys are system media-key events. Tab muting uses the Accessibility API, which was already granted.

**Known limit:** if the app quits while the mic is muted, the mic stays at 0 until it's unmuted (by voice or in Sound settings).
